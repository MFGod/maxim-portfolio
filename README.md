# Портфолио Максима Жихарева

Интерактивное портфолио в метафоре рабочего стола: окна, док, системная панель,
терминал. Резюме читается на сайте как веб-документ; PDF лежит отдельной ссылкой.

Прод: https://maxim-zhikharev.vercel.app

## Стек

Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS v4, Motion, Lucide.
Перетаскивание и изменение размеров окон написаны на Pointer Events, без библиотек.

## Команды

```bash
npm run dev        # разработка
npm run verify     # типы + линт + тесты + сборка
npm run test       # только тесты
npm run format     # prettier
```

## Как всё устроено

### Контентный слой

Весь текст сайта лежит в `src/data/` и типизирован в `src/types/resume.ts`.
В JSX захардкоженного текста резюме нет, UI рендерится из данных.

| Файл                   | Что внутри                                               |
| ---------------------- | -------------------------------------------------------- |
| `data/profile.ts`      | имя, должность, контакты, summary                        |
| `data/experience.ts`   | места работы, связь с проектами через `projectSlugs`     |
| `data/projects.ts`     | проекты: стек, задача, решение, вклад, ссылки            |
| `data/skills.ts`       | технологии по категориям                                 |
| `data/education.ts`    | образование и языки                                      |
| `data/about.ts`        | текст About.app                                          |
| `data/applications.ts` | реестр приложений: иконки, маршруты, размеры окон        |
| `data/system.ts`       | версии стека для «О системе», читаются из `package.json` |
| `data/source-tour.ts`  | фрагменты исходников для «Исходного кода»                |

Правка резюме сводится к правке одного файла в `data/`. Тесты в
`test/resume-data.test.ts` следят за согласованностью связей опыт ↔ проекты.

Поля `problem` и `solution` заполнены там, где формулировка есть в исходном
резюме. `null` означает «не зафиксировано»: UI такие блоки не рисует.

### Приложения

Пятнадцать программ, все через один реестр `data/applications.ts` и одну
ветку в `AppContent`. Содержательные: Резюме, Проекты, Обо мне, Опыт, Стек,
Карта карьеры, Контакты. Служебные: Мой компьютер, Настройки. Инженерные:

- Терминал отдаёт те же данные командами: `help`, `whoami`, `about`, `skills`,
  `experience`, `projects`, `resume`, `github`, `contact`, `arcade`,
  `open <цель>`, `ls`, `clear`. История стрелками, `Tab` дополняет команду.
- Исходный код ведёт экскурсию по архитектуре: путь, назначение, зона
  ответственности и фрагмент файла. `test/source-tour.test.ts` ищет каждый
  фрагмент в его файле по содержимому, так что показанный код совпадает с
  рабочим, а правка выше по файлу витрину не ломает.
- О системе показывает версии стека из `package.json`, описание модулей и среду
  выполнения: браузер, устройство, вьюпорт, тема, маршрут.
- Мониторинг собирает живые показатели: FPS, память (там, где Chromium её
  отдаёт), время загрузки из Navigation Timing, список открытых окон.
  Показатель, которого браузер не отдаёт, помечен «Недоступно».
- GitHub тянет публичные репозитории через GitHub API: разбор ответа в
  `lib/github.ts`, кэш на сессию, отдельные состояния загрузки, исчерпанного
  лимита и сетевой ошибки. Портфолио не зависит от доступности API.
- Аркада держит три маленькие игры и общую таблицу результатов. Единственная
  часть портфолио с серверной стороной, см. ниже.

### Аркада и таблица результатов

Игры лежат в `components/applications/arcade/`, правила вынесены отдельными
чистыми модулями в `lib/arcade/`, чтобы их можно было проверить тестами без DOM.
Активная игра одна: остальные подключаются лениво и не смонтированы.

Очки считает сервер. Клиент присылает показатели забега: длины сложившихся линий
с номером каскада, число поставленных блоков, число пройденных раундов. Счёт из
них выводит `lib/arcade/scoring.ts`, и тот же модуль показывает игроку
предварительный результат. Формула одна на обе стороны, поэтому расходиться
нечему.

Перед партией выдаётся подписанный HMAC токен запуска (`lib/arcade/session.ts`)
со временем старта и одноразовым `nonce`. При отправке сервер проверяет подпись,
срок, одноразовость, тип игры, имя и правдоподобность забега: минута «Трёх в
ряд» не может уложиться в пять секунд, а четыреста блоков в полторы. Это
отсечение очевидных манипуляций; полноценная проверка требовала бы повтора
партии на сервере.

Хранилище живёт в Upstash Redis по REST, без клиентской библиотеки: sorted set
на игру, `ZADD` / `ZREVRANK` / `ZRANGE … REV`. Без переменных окружения
включается запасной драйвер в памяти инстанса: аркада работает целиком, но
таблица обнуляется при перезапуске, и интерфейс честно об этом пишет.

| Переменная                 | Зачем                                            |
| -------------------------- | ------------------------------------------------ |
| `UPSTASH_REDIS_REST_URL`   | адрес хранилища таблицы                          |
| `UPSTASH_REDIS_REST_TOKEN` | токен доступа к нему                             |
| `ARCADE_SECRET`            | ключ подписи запусков, `openssl rand -base64 32` |

### Оконный менеджер

В `src/lib/window-manager/` один редьюсер и один источник правды. Окна не хранят
собственного состояния.

```ts
type WindowInstance = {
  id: string;
  app: AppId;
  payload: { slug: string } | null;
  status: 'normal' | 'minimized' | 'maximized';
  rect: { x: number; y: number; width: number; height: number };
  restoreRect: Rect | null;
};
```

- z-index задаётся позицией в `order`. Инкрементируемого счётчика нет.
- Рабочая область равна вьюпорту минус системная панель и док. При ресайзе окна
  вписываются обратно (`fitToWorkspace`).
- Идентификатор окна равен `AppId`, а для карточки проекта `project:<slug>`.
  Повторное открытие приложения разворачивает существующее окно.

### Производительность перетаскивания

`src/hooks/use-window-gesture.ts`. Во время жеста геометрия пишется прямо в
CSS-переменные узла внутри `requestAnimationFrame`; React не перерисовывается ни
разу. Состояние коммитится один раз на `pointerup`.

Позиционирование и анимация разнесены по разным узлам: внешний держит
`transform: translate3d(...)`, внутренний отвечает за `scale` и `opacity` от
Motion. В одном узле они конфликтуют: Motion перезаписывает `transform`.

Две ловушки, на которые легко наступить повторно:

1. Перетаскивание не должно начинаться на кнопке. Заголовок делает
   `setPointerCapture`, и тогда `pointerup` уходит заголовку, а не кнопке: клик
   не случается, окно перестаёт закрываться. Отсекается в `useWindowGesture`,
   где жест `move` игнорирует цели внутри `button, a, input, select, textarea`.
2. `transform` принадлежит внешнему узлу. Любая анимация трансформации на нём
   сотрёт позицию окна.

### Маршруты и SEO

Корень сайта отдаёт карту карьеры: посетитель попадает в мир сразу, минуя
оболочку. Рабочий стол живёт по адресу `/desktop`, и выход из мира ведёт туда.

Каждое окно имеет свой адрес: `/resume`, `/projects`, `/projects/:slug`,
`/about`, `/experience`, `/skills`, `/contact`, `/arcade`. Открытие ссылки
сразу показывает нужное окно поверх рабочего стола. Старые адреса карты,
`/world` и `/experience/map`, ведут редиректом на корень.

Контент приложений подключён статически, поэтому попадает в серверный HTML:
на `/resume` в разметке лежит полное резюме, а не пустой контейнер. Все страницы
пререндерятся статически. Адресная строка следует за активным окном через
`history.replaceState`; `popstate` возвращает окна в соответствие адресу.

### Карта карьеры

Трёхмерный мир, по которому карьерный путь проходят ногами. Места работы стоят
станциями маршрута, проекты рядом с ними, резюме лежит книгой, которую можно
раскрыть. Сцена на three.js, геометрия приезжает отдельным хостингом
(см. «Ассеты мира не лежат в репозитории»).

Карта служит точкой входа в портфолио. Она занимает весь вьюпорт мимо оболочки,
рабочий стол под ней не смонтирован. В реестре программ карта помечена
`opensAs: 'page'`: док, ярлык, поиск и «Мой компьютер» ведут в неё переходом на
корень. Обратная дорога лежит в меню мира, пункт «На рабочий стол».

Сцена весит 20 МБ, поэтому решение о запуске принимается **до** первого
загруженного байта: `lib/world/capability.ts`, чистая функция, проверяется
тестом без браузера. При отказе рисуется плоский план из тех же координат и
список глав со ссылками на проекты.

Уровень отрисовки выбирается там же. `light` снимает тени с первого кадра и
вдвое опускает потолок площади кадра. Проба качества внутри сцены умеет то же
самое, но срабатывает после тридцати медленных кадров; на телефоне это те
секунды, когда посетитель решает, оставаться ли.

Экранного затенения (`GTAOPass`) в мире нет. Оно стоило 8.8 мс из 21.4, сорок
один процент кадра, ради тени в складках, которую замечают только на двух
кадрах рядом. Без него мир идёт за 12.6 мс и укладывается в шестьдесят кадров с
запасом. Вместе с проходом ушла его обслуга: патч ветра в материал подмены,
пряталки для гряды облаков и ковра листвы, ступень деградации в пробе качества,
переключатель в меню. Атрибут веса качания в вершине остался: с ним одиннадцать
шейдерных программ под одиннадцать высот схлопнулись в одну.

Меню мира разрезано на две вкладки, «Мир» и «Настройки». Граница проведена по
частоте обращения: книга и выход нужны постоянно, камера и звук один раз за
сеанс. Прежде до выхода приходилось проходить взглядом через разделы настроек,
а на экране 800×450 раскрытая панель занимала кадр от кромки до кромки. Открыта
«Мир»; выбранная вкладка переживает закрытие панели.

Камера открывается **от первого лица**. По миру ходят, и первое же движение
мыши в орбите уводило камеру вокруг точки вместо поворота головы. Значение одно
на состояние меню и на саму ригу (`INITIAL_MODE` в
`components/world/world-canvas.tsx`): рига поднимается орбитой и о выборе
интерфейса не знает, поэтому положение ей задаётся явно, иначе переключатель
врал бы с первого кадра.

Нижняя полоса водит по миру, а не по главам резюме. Двадцать две остановки идут
в том порядке, в каком мир осмотрен вживую, но сама остановка знает только свой
кадр: ни `positionId`, ни главы у неё нет. Пока номер шёл от глав, счётчик врал:
«на путь» с первого кадра переносило на третью остановку, потому что первые две
принадлежат входу и ни одной главе не приписаны. Кнопка «На путь» вместе с
прогрессом по главам убрана. Резюме живёт в книге и в подписях на земле.

### Фоновая музыка

Раздел «Звук» во вкладке «Настройки»: две записи на выбор, тишина и ползунок
громкости. По умолчанию играет «Lost Frontier» на 20%, выключатель лежит в двух
движениях. Зазвучит запись не сразу: браузер не даёт запустить звук до первого
действия посетителя, поэтому она поднимается с первым касанием или нажатием
клавиши. Отказ `play()` здесь считается состоянием, а не ошибкой.

Пустое хранилище и неизвестное имя разбираются по-разному. Пустое означает «ещё
не выбирали», там играет запись по умолчанию. Неизвестное имя осталось от
выбора, который мы больше не понимаем, и сводится к тишине: подменять чужое
решение музыкой нельзя.

Звук ведёт `lib/world/ambience-store.ts`, модуль вне React, по образцу
`settingsStore`. В хуке этому места нет: `HTMLAudioElement` живёт своим
временем, и два быстрых переключения в меню оставили бы после себя два
независимых таймера громкости. Опись записей лежит отдельно
(`lib/world/ambience.ts`), чистыми данными под тестом. Там же разбор
сохранённой громкости: содержимое хранилища приходит извне, а `volume` вне
отрезка [0, 1] элемент не принимает, он бросает.

Ползунок применяется к играющей записи сразу, без затухания: его тянут пальцем,
и плавный переход за ним читался бы залипанием. Затухание осталось на смене
записи и на уходе в тишину.

Записи свободные. Мир сделан по мотивам Elden Ring, но её саундтрек принадлежит
Bandai Namco и FromSoftware, и на сайте ему места нет.

| Запись          | Автор                           | Лицензия                                                  |
| --------------- | ------------------------------- | --------------------------------------------------------- |
| «Lost Frontier» | Kevin MacLeod (incompetech.com) | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |
| «Heavy Heart»   | Kevin MacLeod (incompetech.com) | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |

Атрибуция CC BY входит в условия лицензии, поэтому она считается из самой описи
и показывается под списком в меню: новая запись не может приехать без подписи.
Названия по той же причине не переводятся, лицензия требует настоящее имя
произведения.

Файлы пережаты для веба: mp3 96 кбит/с, громкость выровнена по `loudnorm I=-20`,
на входе и выходе добавлено затухание. Запись играет по кругу, и без затухания
стык щёлкал бы на каждом повторе. Полная опись с адресами оригиналов лежит рядом
с файлами, в `public/world/ambience/CREDITS.txt`.

### Десктоп, планшет, телефон

Ниже 768px оконный менеджер не монтируется вообще: приложения открываются на весь
экран, док заменён нижней навигацией, перетаскивание и ресайз отсутствуют.
Переключает `matchMedia`, а не CSS-скрытие.

Выше этой границы работает оконный режим, на планшете тоже. Что зависит от
пальца, следует за `pointer: coarse`: зоны захвата у краёв окна вырастают с
шести пикселей до шестнадцати, а мир в виде от первого лица получает экранный
стик вместо WASD. Осмотр с места считает дельту указателя сам:
`movementX`/`movementY` Safari на iOS не отдаёт, и на нём это был единственный
неработающий жест.

Раскладка внутри окон считается по ширине **контейнера** (`@container`), не
вьюпорта: окно на 420 пикселей одинаково тесно на большом мониторе и на
телефоне.

### Дизайн-система

Токены лежат в `src/app/globals.css` (`@theme`): поверхности, границы, три
уровня текста, акцент, типографическая шкала, радиусы, тени, свечение, тайминги,
слои. Произвольных значений в компонентах нет.

Визуальный язык строится на тёмном тёплом основании, приглушённом золоте и
пергаментном тексте. Шрифтов два: гротеск несёт весь текст, антиква
(`--font-display`) остаётся именам и заголовкам разделов. Свет живёт в двух
токенах свечения и в слоях обоев (`--wp-*`): зарево, туман, зерно, виньетка.

Контраст: самый приглушённый уровень текста держит 4.5:1 на самой светлой из
используемых поверхностей.

Фоновое движение, туман и дыхание свечения, помечено `data-ambient` и
останавливается совсем при `prefers-reduced-motion` или уровне движения
«уменьшенный»: ускорять бесконечный цикл бессмысленно.

### Доступность

Работа с клавиатуры без сочетаний с модификаторами: `Esc` закрывает активное
окно, `/` открывает поиск по программам и проектам, `?` показывает список
сокращений. В поиске работают стрелки и `Enter`, в терминале история стрелками,
`Tab` дополняет команду. Заголовок окна фокусируется и двигается стрелками
(шаг 24 px, с `Shift` 4 px). Одноклавишные сокращения отключаются в настройках
доступности.

Кольцо фокуса появляется только при навигации с клавиатуры: `Tab` ставит на
`<html>` признак `data-nav`, нажатие указателем его снимает. Собственное кольцо
браузера погашено: оно синее, мимо палитры, и всплывает после любой клавиши на
элементе, в который просто кликнули. Своё кольцо волосяное, цветом акцента,
и следует за выбранной темой и акцентом. Подсветка фоном и подъём под фокусом
живут под тем же признаком: варианты `kbd-focus` и `group-kbd-focus`.

Свёрнутое окно остаётся в DOM, но помечено `inert` и уходит из табуляции.
Скрытые док, ярлыки и системная панель убираются через `display: none`, поэтому
не остаются в таб-порядке. Если выключить всё сразу, на рабочем столе появляется
кнопка «Открыть программу», иначе окно стало бы нечем открыть.
`prefers-reduced-motion` отключает анимации и стартовую заставку.

## Деплой на Vercel

Сборка обычная: `next build`, без адаптеров и внешних шагов. Настроить нужно две
вещи: переменные окружения и ассеты мира.

### Переменные окружения

| Переменная                     | Обязательна | Что будет без неё                                              |
| ------------------------------ | ----------- | -------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`         | нет         | canonical, Open Graph и sitemap уедут на адрес по умолчанию    |
| `NEXT_PUBLIC_WORLD_ASSETS_URL` | **да**      | «Карта карьеры» покажет отказ загрузки: ассетов в сборке нет   |
| `ARCADE_SECRET`                | **да**      | аркада вернёт ошибку вместо таблицы: подписывать запуски нечем |
| `UPSTASH_REDIS_REST_URL`       | нет         | рекорды лягут в память инстанса и потеряются между запросами   |
| `UPSTASH_REDIS_REST_TOKEN`     | нет         | то же                                                          |

### Ассеты мира не лежат в репозитории

`public/world/` занимает 20 МБ: карта, фигуры, книга, декодер DRACO и фоновые
записи. Всё это исключено `.gitignore`. Vercel собирает из репозитория, поэтому
на проде этих файлов нет, и без внешнего адреса мир остаётся без геометрии.

Ассеты живут отдельным репозиторием на GitHub Pages, а приложение узнаёт о нём
из `NEXT_PUBLIC_WORLD_ASSETS_URL`. Единственная точка склейки, `WORLD_ASSETS` в
`src/lib/world/assets.ts`, собирает все пути к ассетам, поэтому смена хостинга
остаётся правкой одной переменной.

Локально переменную можно не ставить: по умолчанию адрес указывает на
`public/world` рядом с приложением.

### Инструменты подбора в прод-сборку не входят

Расстановка фигур, снимки ракурсов, пометки инстансов, замеры книги и счётчик
кадров живут за флагом `DEV_TOOLS` (`src/lib/world/dev-tools.ts`) и подключаются
динамическим импортом из `world-dev-overlay.tsx`. Флаг записан литералом,
который сборщик сворачивает в `false`, поэтому ни оверлей, ни `dev-console`, ни
шесть модулей `dev-*` в бандл страницы не попадают. Проверено запросами на живой
прод-сборке: чанк не грузится, `window.__world` отсутствует.

Отсюда же следует, что `next build && next start` локально инструментов не
покажет. Они существуют только в `next dev`.

## Что осталось незаполненным

- Скриншоты проектов. Поле `visuals` у всех проектов пустое; галерея не
  рендерится, пока в нём ничего нет. Коммерческие проекты помечены
  `confidential: true`: у них не должно быть ни публичных ссылок, ни реальных
  интерфейсов.
- Поля `problem` и `solution` у части проектов равны `null`, потому что в
  исходном резюме этих формулировок нет.
