# Портфолио — Максим Жихарев

Интерактивное портфолио в метафоре рабочего стола: окна, док, системная панель,
терминал. Резюме читается на сайте как веб-документ; PDF лежит отдельной ссылкой.

Прод: https://maxim-zicharev-resume.vercel.app

## Стек

Next.js 16 (App Router) · React 19 · TypeScript strict · Tailwind CSS v4 · Motion · Lucide.
Перетаскивание и изменение размеров окон — собственная реализация на Pointer Events,
без библиотек.

## Команды

```bash
npm run dev        # разработка
npm run verify     # типы + линт + тесты + сборка
npm run test       # только тесты
npm run format     # prettier
```

## Как всё устроено

### Контентный слой

Весь текст сайта лежит в `src/data/` и типизирован в `src/types/resume.ts`.
В JSX захардкоженного текста резюме нет — UI рендерится из данных.

| Файл                   | Что внутри                                                |
| ---------------------- | --------------------------------------------------------- |
| `data/profile.ts`      | имя, должность, контакты, summary                         |
| `data/experience.ts`   | места работы, связь с проектами через `projectSlugs`      |
| `data/projects.ts`     | проекты: стек, задача, решение, вклад, ссылки             |
| `data/skills.ts`       | технологии по категориям                                  |
| `data/education.ts`    | образование и языки                                       |
| `data/about.ts`        | текст About.app                                           |
| `data/applications.ts` | реестр приложений: иконки, маршруты, размеры окон         |
| `data/system.ts`       | версии стека для «О системе» — читаются из `package.json` |
| `data/source-tour.ts`  | фрагменты исходников для «Исходного кода»                 |

Правка резюме — это правка одного файла в `data/`. Тесты в
`test/resume-data.test.ts` следят за согласованностью связей опыт ↔ проекты.

Поля `problem` и `solution` заполнены там, где формулировка есть в исходном
резюме. `null` означает «не зафиксировано»: UI такие блоки не рисует.

### Приложения

Четырнадцать программ, все — через один реестр `data/applications.ts` и одну
ветку в `AppContent`. Содержательные: Резюме, Проекты, Обо мне, Опыт, Стек,
Контакты. Служебные: Мой компьютер, Настройки. Инженерные:

- **Терминал** — те же данные командами: `help`, `whoami`, `about`, `skills`,
  `experience`, `projects`, `resume`, `github`, `contact`, `arcade`,
  `open <цель>`, `ls`, `clear`. История стрелками, `Tab` дополняет команду.
- **Исходный код** — экскурсия по архитектуре: путь, назначение, зона
  ответственности и фрагмент файла. `test/source-tour.test.ts` ищет каждый
  фрагмент в его файле по содержимому, так что показанный код совпадает с
  рабочим, а правка выше по файлу витрину не ломает.
- **О системе** — версии стека из `package.json`, описание модулей, среда
  выполнения: браузер, устройство, вьюпорт, тема, маршрут.
- **Мониторинг** — живые показатели: FPS, память (там, где Chromium её отдаёт),
  время загрузки из Navigation Timing, список открытых окон. Показатель, которого
  браузер не отдаёт, помечен «Недоступно».
- **GitHub** — публичные репозитории через GitHub API: разбор ответа в
  `lib/github.ts`, кэш на сессию, отдельные состояния загрузки, исчерпанного
  лимита и сетевой ошибки. Портфолио не зависит от доступности API.
- **Аркада** — три маленькие игры и общая таблица результатов. Единственная
  часть портфолио с серверной стороной, см. ниже.

### Аркада и таблица результатов

Игры лежат в `components/applications/arcade/`, правила — отдельными чистыми
модулями в `lib/arcade/`, чтобы их можно было проверить тестами без DOM.
Активная игра одна: остальные подключаются лениво и не смонтированы.

**Очки считает сервер.** Клиент отправляет не счёт, а показатели забега —
длины сложившихся линий с номером каскада, число поставленных блоков, число
пройденных раундов. Счёт из них выводит `lib/arcade/scoring.ts`, и тот же
модуль показывает игроку предварительный результат: одна формула на обе
стороны, расхождение невозможно.

Перед партией выдаётся подписанный HMAC токен запуска (`lib/arcade/session.ts`)
со временем старта и одноразовым `nonce`. При отправке сервер проверяет подпись,
срок, одноразовость, тип игры, имя и правдоподобность забега: минута «Трёх в
ряд» не может уложиться в пять секунд, а четыреста блоков — в полторы. Это не
античит, а отсечение очевидных манипуляций — полноценная проверка требовала бы
повтора партии на сервере.

Хранилище — Upstash Redis по REST, без клиентской библиотеки: sorted set на
игру, `ZADD` / `ZREVRANK` / `ZRANGE … REV`. Без переменных окружения включается
запасной драйвер в памяти инстанса: аркада работает целиком, но таблица
обнуляется при перезапуске, и интерфейс честно об этом пишет.

| Переменная                 | Зачем                                            |
| -------------------------- | ------------------------------------------------ |
| `UPSTASH_REDIS_REST_URL`   | адрес хранилища таблицы                          |
| `UPSTASH_REDIS_REST_TOKEN` | токен доступа к нему                             |
| `ARCADE_SECRET`            | ключ подписи запусков, `openssl rand -base64 32` |

### Оконный менеджер

`src/lib/window-manager/` — один редьюсер, один источник правды. Окна не хранят
собственного состояния.

```ts
type WindowInstance = {
  id: string;
  app: AppId;
  payload: { slug: string } | null;
  status: 'normal' | 'minimized' | 'maximized';
  rect: { x: number; y: number; width: number; height: number };
  restoreRect: Rect | null;
};
```

- **z-index — это позиция в `order`.** Инкрементируемого счётчика нет.
- **Рабочая область** = вьюпорт минус системная панель и док. При ресайзе окна
  вписываются обратно (`fitToWorkspace`).
- **Идентификатор окна** = `AppId`, а для карточки проекта — `project:<slug>`.
  Повторное открытие приложения разворачивает существующее окно.

### Производительность перетаскивания

`src/hooks/use-window-gesture.ts`. Во время жеста геометрия пишется прямо в
CSS-переменные узла внутри `requestAnimationFrame`; React не перерисовывается ни
разу. Состояние коммитится один раз на `pointerup`.

Позиционирование и анимация разнесены по разным узлам: внешний держит
`transform: translate3d(...)`, внутренний — `scale`/`opacity` от Motion. В одном
узле они конфликтуют: Motion перезаписывает `transform`.

Две ловушки, на которые легко наступить повторно:

1. **Перетаскивание не должно начинаться на кнопке.** Заголовок делает
   `setPointerCapture`, и тогда `pointerup` уходит заголовку, а не кнопке: клик
   не случается, окно перестаёт закрываться. Отсекается в `useWindowGesture` —
   жест `move` игнорирует цели внутри `button, a, input, select, textarea`.
2. **`transform` принадлежит внешнему узлу.** Любая анимация трансформации на нём
   сотрёт позицию окна.

### Маршруты и SEO

Каждое приложение имеет свой адрес: `/resume`, `/projects`, `/projects/:slug`,
`/about`, `/experience`, `/skills`, `/contact`, `/arcade`. Открытие ссылки сразу
показывает нужное окно.

Контент приложений подключён статически, поэтому попадает в серверный HTML:
на `/resume` в разметке лежит полное резюме, а не пустой контейнер. Все страницы
пререндерятся статически. Адресная строка следует за активным окном через
`history.replaceState`; `popstate` возвращает окна в соответствие адресу.

### Десктоп и мобильный — два интерфейса

Ниже 768px оконный менеджер не монтируется вообще: приложения открываются на весь
экран, док заменён нижней навигацией, перетаскивание и ресайз отсутствуют.
Переключение — `matchMedia`, не CSS-скрытие.

### Дизайн-система

Токены — в `src/app/globals.css` (`@theme`): поверхности, границы, три уровня
текста, акцент, типографическая шкала, радиусы, тени, свечение, тайминги, слои.
Произвольных значений в компонентах нет.

Визуальный язык — тёмное тёплое основание, приглушённое золото и пергаментный
текст. Шрифтов два: гротеск несёт весь текст, антиква (`--font-display`) —
только имена и заголовки разделов. Свет живёт в двух токенах свечения и в слоях
обоев (`--wp-*`): зарево, туман, зерно, виньетка.

Контраст: самый приглушённый уровень текста держит 4.5:1 на самой светлой из
используемых поверхностей.

Фоновое движение — туман и дыхание свечения — помечено `data-ambient` и
останавливается совсем при `prefers-reduced-motion` или уровне движения
«уменьшенный»: ускорять бесконечный цикл бессмысленно.

### Доступность

Работа с клавиатуры без сочетаний с модификаторами: `Esc` закрывает активное
окно, `/` открывает поиск по программам и проектам, `?` показывает список
сокращений. В поиске — стрелки и `Enter`, в терминале — история стрелками,
`Tab` дополняет команду. Заголовок окна фокусируется и двигается стрелками
(шаг 24 px, с `Shift` — 4 px). Одноклавишные сокращения отключаются в настройках
доступности.

Кольцо фокуса появляется только при навигации с клавиатуры: `Tab` ставит на
`<html>` признак `data-nav`, нажатие указателем его снимает. Собственное кольцо
браузера погашено — оно синее, мимо палитры, и всплывает после любой клавиши на
элементе, в который просто кликнули. Своё кольцо — волосяное, цветом акцента,
и следует за выбранной темой и акцентом. Подсветка фоном и подъём под фокусом
живут под тем же признаком: варианты `kbd-focus` и `group-kbd-focus`.

Свёрнутое окно остаётся в DOM, но помечено `inert` — в обход табуляции.
Скрытые док, ярлыки и системная панель убираются через `display: none`, поэтому
не остаются в таб-порядке. Если выключить всё сразу, на рабочем столе появляется
кнопка «Открыть программу» — иначе окно стало бы нечем открыть.
`prefers-reduced-motion` отключает анимации и стартовую заставку.

## Что осталось незаполненным

- **Скриншоты проектов.** Поле `visuals` у всех проектов пустое; галерея не
  рендерится, пока в нём ничего нет. Коммерческие проекты помечены
  `confidential: true`: у них не должно быть ни публичных ссылок, ни реальных
  интерфейсов.
- **`problem` / `solution`** у части проектов — `null`, потому что в исходном
  резюме этих формулировок нет.
